# X5-B1: FYERS native option-chain adapter (offline, data only)

New file: `services/x5/fyers_adapter_v1.py`. Consumes an already-returned `FyersOptionChainProviderV2.get_option_chain(...)` mapping (`rows` from `normalize_option_chain`). It never imports the FYERS SDK, makes provider requests, modifies previous X1–X4 code, selects option contracts, calculates metrics, calls brokers, touches PAPER journals or changes the Brain V1 registry.

## Preconditions and evidence ownership

- An exact `X5ContractV1` for NIFTY/NFO, SENSEX/BFO or CRUDEOILM/GOLDM/NATGASMINI on MCX, with the canonical FYERS underlying root and separately sourced metadata. The caller must verify the contract; the adapter cannot upgrade `PROVISIONAL` to `VERIFIED`.
- Provider response must report `FYERS`, exact underlying, `data_only=True`, `live_execution_eligible=False`, one native-chain request and zero per-contract depth requests. Provider-selected expiry date, epoch and exactly one matching `expiryData` entry must agree with the canonical expiry. Every row must provide that exact date or epoch; missing per-row expiry is **rejected** until an independently verified binding mechanism is added.
- An exact `canonical_ids_by_symbol` mapping from a trusted resolver/master, and an independently obtained, timezone-aware `observed_at_by_symbol` for **every** CE/PE row. No fallback to capture time, expiry time, `tt`, current time, assumed observation time or symbol parsing for canonical option identity. Source times cannot exceed capture or replay as-of time.
- `captured_at` (retrieval) and `as_of` (research checkpoint) are separate. Retrospective captures require `historical_retrieval=True` and cannot claim contemporaneous point-in-time proof. `point_in_time_verified=True` remains a caller assertion requiring verification flags, not cryptographic proof.
- Numeric `oi`, `volume`, `bid`, `ask`, `ltp` are retained with no unit conversion. OI/volume/premium verification flags and named units are explicit, independent inputs. The provider's `oich` is **not** necessarily absolute signed OI change. By default it is omitted from `change_in_open_interest`; only explicitly independently proven absolute-change semantics with per-symbol comparable baseline IDs allow promotion.
- No verified IV or Greeks can be derived from the existing normalized rows. Those fields remain absent even if a raw FYERS provider payload has them. Underlying price verification requires its own source ID, time, correct unit and freshness. All captured row timestamps and underlying time are checked against the research checkpoint.
- Zero and missing OI/volume are distinct. Incomplete CE/PE pairs remain incomplete, never filled or extrapolated. Whole-chain research readiness refers only to the **captured strike window**, not all strikes on the exchange.
- The adapter passes the capture through X5-A `validate_x5_chain_v1`, preserving `AVAILABLE`, `PARTIAL`, `UNAVAILABLE`, blockers and metric readiness. An adapter output is frozen and contains both a capture hash (via capture) and a canonical hash of selected normalized source payload fields. Source references are supplied by the caller and must not include secrets.

## Still not proven

Test fixtures are not live provider evidence. Neither FYERS `oi` units, volume units, `oich` semantics, individual row timestamp provenance, option-symbol metadata nor exchange-wide strike coverage has been independently certified. If a real response lacks required per-row expiry/time or canonical IDs, the adapter raises rather than manufacturing evidence. To support that response safely, build a separate recorded, externally validated mapping or additional read-only capture contract in a subsequent phase. No live order eligibility or PAPER certification follows from X5-B1.
